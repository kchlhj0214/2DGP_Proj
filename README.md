# 참는 데도 용량이 있습니다

Python + pico2d로 만드는 단일 원형 경기장 액션 게임.
현재는 이미지 없이 히트박스로 방어·패링·광선과 근접/원거리 적의 웨이브를 시험할 수 있습니다.

## 실행

Python 3.13과 `requirements.txt`의 pico2d를 사용합니다.

```powershell
python -m pip install -r requirements.txt
python main.py
```

이 작업 PC에는 검증용 Python 3.13.11을 `.scratch/python` 안에 준비했습니다.
VS Code의 기본 빌드 작업(Ctrl+Shift+B)은 해당 Python으로 데이터를 검증하고 실행합니다.
다른 PC에서는 설치한 Python 인터프리터를 선택하고 `main.py`를 실행하면 됩니다.
검증용 도구와 내려받은 강의 저장소는 Git 및 배포 대상에서 제외합니다.

- 기본 1280×720 창 모드로 시작합니다. 작은 화면에서는 바탕화면의 85% 안에 맞춰 축소합니다.
- WASD: 이동. 대각선 속도 보정 적용.
- 캐릭터는 경기장 가장자리에서도 항상 화면 중앙에 위치합니다.
  원 밖의 지면도 보이지만 이동할 수 없으며, 경기장 크기는 유지합니다.
- 마우스 이동: 바라보는 방향과 전방 90도 방어 방향 조절.
- 우클릭 누르기: 패링 시도. 성공 여부와 관계없이 1초간 이동·재입력 잠금.
- 우클릭 유지: 1초 잠금 후 기본 방어. 기본 방어에는 에너지 축적이 없습니다.
- 왼쪽 클릭: 축적 에너지를 모두 소비해 광선 발사. 축적 0일 때는 발사할 수 없습니다.
- ESC: 일시정지/재개. R: 전체 초기화 후 1웨이브 혼합 구성으로 다시 시작.
- 1/2/3/4: 해당 웨이브로 이동. 4는 보스 미구현 상태로 적 없이 대기합니다.
- 8: 근접만 / 9: 원거리만 / 0: 혼합으로 현재 웨이브를 처음부터 다시 생성합니다.
- 창 오른쪽 위의 X 버튼으로 프로그램을 종료합니다. Alt+F4도 사용할 수 있습니다.
- 다른 창으로 전환하면 이동 입력을 비우고 멈춥니다.
- 청록색 직사각형이 플레이어이자 히트박스입니다.
- 경기장 경계에는 직사각형의 하단 절반만 사용합니다. 가운데 선 아래 영역이
  원 안에 남으며, 상단 절반은 캐릭터의 키와 시점을 고려해 경계를 넘을 수 있습니다.
- 격자 한 칸은 1m, 강조선 간격은 5m입니다. 노란 사각형은 입구 위치 표시입니다.

## 전투 훈련

- 패링한 공격당 에너지 10, 최대 40. 10·20·30에서 다음 단계로 올라갑니다.
- 단계별 패링 성공 구간은 0.30 / 0.22 / 0.15 / 0.10초입니다.
- 첫 패링 성공부터 전 방향 무적 1초. 추가 패링으로 무적 시간이 늘어나지 않습니다.
- 같은 패링 구간의 공격은 각각 축적되지만, 근접 적 1마리만 1.5초간 기절합니다.
- 기본 방어는 전방 90도 피해를 막으며, 이동 속도는 7km/h로 낮아집니다.
- 광선은 발사 방향을 고정하고 이동하는 주인공을 따라가며 경기장 끝까지 관통합니다.
  발사 즉시, 0.5초, 1초에 피해를 주고 1.5초에 사라집니다.
- 주인공 체력 100, 근접 적 체력 60. 칼 피해는 10입니다.
- 적은 10km/h로 추적하다가 멈춰 방향을 고정하고 0.6초 예고 후 전방 90도를 벱니다.
  실제 칼 히트박스는 길이 2m·두께 0.25m이고 0.25초 동안 회전합니다.
- 초록 부채꼴은 패링 가능 구간, 주황은 방패 들기 잠금/적 공격 예고,
  파랑은 기본 방어, 노랑은 칼의 실제 판정, 하늘색 직사각형은 광선입니다.
- 적을 모두 쓰러뜨리거나 주인공이 사망하면 R로 다시 시작할 수 있습니다.
- 웨이브는 디버그 숫자 키로만 전환합니다. 이동/종류 변경 시 기존 적·탄환·출현 대기를
  모두 지우고 새로 생성하며, 주인공의 위치·체력·에너지는 유지합니다.
- 1·2웨이브 각 12마리, 3웨이브 16마리. 혼합은 입구별 근접 2+원거리 1 또는 근접 3+원거리 1.
  상하좌우에서 동시에 출현을 시작하고 각 입구의 다음 적은 0.3초 후에 나옵니다. 출현 예고는 없습니다.
- 원거리 적은 사거리 10m 안에서 예고 없이 3초 간격으로 직선 탄환을 발사합니다.
  몸체/체력/이동은 근접 적과 같고, 탄환 속도는 8m/s, 지름 0.3m, 피해 10입니다.
- 원거리 탄환도 패링당 에너지 10을 주지만 원거리 적을 스턴하지 않습니다.
  탄환은 방어·패링·광선·적중·경기장 경계에서 사라집니다.

세부 규칙과 초기 수치는 [전투 합의 기록](docs/combat-decisions.md)에 정리했습니다.
웨이브·원거리 규칙은 [웨이브 합의 기록](docs/wave-debug-decisions.md)을 따릅니다. 보스는 아직 구현하지 않았습니다.

## 확정한 크기

| 항목 | 기준 | 높이 1080 화면 |
| --- | --- | --- |
| 원형 경기장 지름 | 화면 높이 × 1.75 | 1890px |
| 플레이어 높이 | 화면 높이 × 0.05 | 54px |
| 플레이어 너비 | 플레이어 높이 × 0.5 | 27px |

게임 안에서는 화면 세로를 36m로 환산합니다. 경기장 지름 63m, 플레이어는
0.9m × 1.8m입니다. 위치와 판정은 m, 이동 속도는 m/s, 경과 시간은 s로 다루며
그릴 때만 화면 크기에 맞춰 픽셀로 환산합니다. 기본 이동 속도는
기존 7km/h의 두 배인 14km/h입니다.

## 강의 방식과 개발 흐름

분석 근거와 적용 내용은 [강의 적용 기록](docs/lecture-notes.md)에 정리했습니다.

- `main.py`: 시트 검증 및 창 모드 시작·종료.
- `game_framework.py`: 모드 스택, 이벤트 → 갱신 → 그리기, 실제 경과 시간 측정.
- `game_world.py`: 레이어별 객체 관리.
- `play_mode.py`: 훈련 화면, 일시정지·재시작, 경과 시간을 작은 간격으로 나누는 전투 갱신.
- `arena.py`, `player.py`, `camera.py`: 객체별 클래스.
- `defense.py`, `beam.py`: 플레이어 전투 상태와 광선.
- `enemy.py`, `geometry.py`: 적의 행동, 회전 히트박스 충돌.
- `combat_hud.py`: 체력·에너지·상태·조작 안내.
- `wave_manager.py`: 디버그 웨이브 전환과 네 방향 출현 대기열.
- `ranged_enemy.py`, `projectile.py`: 원거리 적과 직선 탄환.
- `data/scale.json`: 크기와 속도의 원본 데이터 시트.
- `data/combat.json`: 전투·축적 단계·근접 적의 원본 시트.
- `data/waves.json`: 웨이브·종류 모드·입구·원거리 적의 원본 시트.
- `tools/generate_data.py`: 빈 셀·수치·참조 검증 후 `game_data.py`, `combat_data.py`, `wave_data.py` 생성.

```powershell
python tools/generate_data.py
python -m unittest discover -s tests -v
```

검사는 화면을 열지 않는 SDL dummy 드라이버를 사용합니다. 실제 pico2d 렌더링,
키 입력 전달, 해상도별 크기, FPS별 이동 거리, 대각선 보정, 원과 직사각형의 경계,
경계에서의 화면 중앙 유지, 포커스 상실과 전투 규칙을 확인합니다.
실제 칼 충돌로 네 번 패링해 에너지 40을 모으고 광선으로 적을 쓰러뜨리는 흐름도 검사합니다.
전체화면에서의 육안 플레이 검증과는 구분합니다.
`shots`에는 검사 중 실제 렌더 버퍼에서 캡처한 화면을 저장합니다.
